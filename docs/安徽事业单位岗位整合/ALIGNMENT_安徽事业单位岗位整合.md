# 对齐文档 - 安徽省事业单位岗位整合

## 任务概述

将安徽省14个地市的事业单位岗位表（共68个Excel文件）整合成统一的总表，并导入到现有的公考管理系统中。

---

## 一、项目上下文分析

### 1.1 现有项目架构

**技术栈**
- 后端：Python 3.11 + Flask + SQLAlchemy
- 数据库：SQLite（开发）/ MySQL（生产）
- 前端：HTML + Tailwind CSS + Alpine.js

**核心模块**
- `gongkao-system`：公考培训管理系统（主系统）
  - 学员管理
  - 课程管理
  - 智能选岗（Position模型）
  - 学习计划

### 1.2 现有数据模型

**Position模型**（`app/models/position.py`）
- 主要服务于：省考/国考岗位
- 核心字段：
  - 年份、考试类型（省考/国考）
  - 地区信息（region_name, city, system_type）
  - 单位信息（department_name）
  - 职位信息（position_name, position_code, position_desc）
  - 招录条件（education, major_requirement, exam_category, recruit_count）
  - 竞争数据（apply_count, competition_ratio, min_entry_score）

**PositionService**（`app/services/position_service.py`）
- 岗位搜索和筛选
- 学员岗位匹配（学历、专业、政治面貌、工作年限、年龄）
- 统计分析

## 三、不确定性和待澄清问题

### 3.1 数据结构不一致问题

**问题**：不同地市的Excel文件，列名和数据格式可能不完全一致

**决策**：
- 需要先遍历所有68个文件，分析列名的一致性
- 建立字段映射表，统一标准化
- 记录异常情况（字段缺失、格式错误）

### 3.2 与现有模型的对齐

**问题**：事业单位岗位字段与公务员岗位字段的差异

**待确认**：
1. **考试类型字段**：
   - 现有：`exam_type` 只有"省考/国考"
   - 新增：是否添加"事业单位"类型？
   - **建议**：使用 `exam_type = '事业单位'`

2. **考试类别字段**：
   - 公务员：A类/B类/C类
   - 事业单位：综合管理类A类、社会科学专技类B类、自然科学专技类C类、中小学教师类D类、医疗卫生类E类
   - **建议**：保持现有字段，直接存储文本

3. **地区层级**：
   - 现有：`city`字段（城市级别）
   - 事业单位：市级 + 区县级
   - **建议**：
     - `city`：地级市（如"合肥市"）
     - `region_name`：区县名（如"肥东县"）

4. **单位类型字段**：
   - 事业单位有：公益一类、公益二类、公益三类
   - **建议**：复用 `system_type` 字段存储

5. **岗位代码唯一性**：
   - 不同地市可能有相同的岗位代码
   - **建议**：唯一约束使用 `year + exam_type + city + region_name + position_code`

### 3.3 导入策略

**问题**：是否需要去重、覆盖还是追加

**待确认**：
- 如果数据库已存在2026年事业单位数据，是否覆盖？
- **建议**：先清空2026年事业单位数据，再导入

### 3.4 数据质量

**问题**：Excel中可能存在的数据问题

**处理策略**：
- 空值处理：允许某些字段为空
- 格式错误：记录日志，人工核查
- 编码问题：统一使用UTF-8

## 七、行业知识和类似工程参考

### 7.1 事业单位与公务员差异

| 维度 | 公务员 | 事业单位 |
|------|--------|----------|
| 编制 | 行政编 | 事业编 |
| 考试类别 | A/B/C类 | A/B/C/D/E类（更细分） |
| 招考单位 | 政府机关 | 学校、医院、科研院所等 |
| 岗位类型 | 综合管理、行政执法 | 管理岗、专业技术岗、工勤岗 |

### 7.2 数据导入最佳实践

1. **分批导入**：每次导入500-1000条，避免内存溢出
2. **事务处理**：使用数据库事务，失败可回滚
3. **进度显示**：实时显示导入进度
4. **日志记录**：详细记录成功/失败/跳过的记录
