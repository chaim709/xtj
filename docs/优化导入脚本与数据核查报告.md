@staticmethod
def calculate_file_hash(file_path: str) -> str:
    """计算文件的MD5 hash值（用于去重）"""
    md5_hash = hashlib.md5()
    with open(file_path, 'rb') as f:
        while chunk := f.read(8192):
            md5_hash.update(chunk)
    return md5_hash.hexdigest()
```

**改进效果**：
- ✅ 自动检测重复文件（基于内容hash，而非文件名）

### 3.2 主要差异来源

#### ① 省直数据扩展（最大差异）

| 项目 | 原始统计 | 数据库 | 差异 |
|------|---------|--------|------|
| 岗位数 | 71 | 674 | **+603** |
| 招聘人数 | 101 | 949 | **+848** |

**原因分析**：
- 省直主文件（637行）使用了大量合并单元格
- 每个"主管部门"下有多个"招聘单位"
- 导入时正确展开了合并单元格，每个招聘单位成为独立岗位
- 核查脚本的统计逻辑过于简单，只统计了有岗位代码的行

**示例**：
```
主管部门（招聘人数）         招聘单位          岗位代码
安徽省教育厅（50人）      安徽卫生健康职业学院    3000001
                        安徽卫生健康职业学院    3000002
                        ...（32个岗位）

核查脚本只统计到1个岗位（第一行），但实际有32个岗位。

## 六、遗留问题与建议

### 6.1 核查脚本的局限性

⚠️  **问题**：核查脚本对合并单元格的处理不够完善

**影响**：
- 省直文件：统计71岗 vs 实际674岗（低估89.5%）
- 合肥文件：统计120岗 vs 实际181岗（低估33.7%）

**原因**：
- 合并单元格在pandas中只有第一行有值
- 简单的行计数无法准确反映真实岗位数
- 需要根据实际数据结构（主管部门→招聘单位→岗位）进行多层统计

**建议**：
1. 在核查脚本中添加合并单元格展开逻辑
2. 使用更复杂的统计算法（分析主管部门和招聘单位的层级关系）
3. 或直接使用数据库数据作为基准
